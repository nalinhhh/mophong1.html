Hướng dẫn & Giới hạn kỹ thuật

Cách chạy để dùng đầy đủ tính năng

  • Đặt file HTML lên máy chủ có HTTPS (Netlify, Vercel, GitHub Pages, Cloudflare Pages — miễn phí).
  • Hoặc chạy trên localhost khi phát triển (dùng npx serve).
  • Mở bằng Chrome (Android) / Safari (iOS) / trình duyệt có WebXR.

AR – Hoạt động được khi nào?

  • ✓ Chrome Android + ARCore: AR đầy đủ.
  • ✗ Safari iOS: không hỗ trợ WebXR → cần dùng giải pháp dự phòng.
  • ✗ Desktop thường: không có camera AR → dùng nút “Xem ở chế độ 3D”.

Dự phòng AR cho iOS / thiết bị khác

  • Bấm “Xuất .glb” ở phân hệ 3D để tải mô hình về máy.
  • Upload file .glb lên máy chủ của bạn (HTTPS).
  • Với iOS: dùng công cụ Reality Converter (miễn phí từ Apple) để chuyển .glb → .usdz, upload lên cùng thư mục.
  • Nhúng mô hình bằng thẻ <model-viewer> — sẽ tự mở AR Quick Look (iOS) hoặc Scene Viewer (Android).

VR nhập vai

  • Chỉ chạy khi có kính VR + trình duyệt hỗ trợ (Meta Quest Browser, Wolvic, Chrome PC + SteamVR).
  • Không thể khắc phục bằng code nếu thiếu phần cứng.
  • Chế độ “3D khám phá” là phương án thay thế đầy đủ trên máy tính/điện thoại.

Lưu tiến độ

Tiến độ 3 trạm được lưu trong localStorage của trình duyệt. Nếu xoá dữ liệu trình duyệt, tiến độ sẽ mất. Bấm “↺ Bắt đầu lại” ở tab Học tập để xoá thủ công.

Nội dung chuyên môn

Nội dung hiện tại là bản mẫu — cần giáo viên duyệt lại. Để thay đổi nội dung:

  • Mở file HTML, tìm object PART_INFO (mục thông tin bộ phận) và LEARN_DATA (mục câu hỏi 3 trạm).
  • Sửa trực tiếp tên bộ phận, câu hỏi, đáp án.
  • Hoặc chuyển 2 object đó sang file noi-dung.json riêng và tải bằng fetch() (đã có sẵn cấu trúc JSON, chỉ cần copy).

Những gì KHÔNG thể khắc phục bằng code

  • AR trên iOS Safari – cần file .usdz được host sẵn.
  • VR nhập vai – cần kính VR + trình duyệt hỗ trợ.
  • HTTPS – cần hạ tầng máy chủ, không phải chỉnh code.
  • Chuyên môn – cần giáo viên duyệt nội dung.
